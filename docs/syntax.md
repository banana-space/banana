# 百科 Markdown 语法

百科文章放在 `content/wiki/`，推荐使用页面包 `条目名/index.md`。编辑源文件后运行 `npm run build`，预处理将副本写入 `.build/content/`，然后交给 Hugo 渲染；源文件不会被构建过程修改。

本页是写给开发者的完整参考，包括实现细节；写给编辑者的说明见网站上的写作指南（`content/help/`）。修改语法时请同时更新两处。

源文件的排版由 `npm run format` 统一（`scripts/format/markdown.mjs`；`npm run format -- --check` 只检查，`tests/format.mjs` 要求 `content/` 已排版）。它只改换行与缩进，不改变构建出的页面：导言区与正文之间空一行；行间公式（`\[ … \]`、`$$ … $$`）的分隔符各占一行，公式各行与开始的那一行同样缩进（公式内部的相对缩进保留，紧挨分隔符的强调标记 `*` 留在分隔符旁）；段落的行不超过 100 列（中日韩字符算 2 列），依次优先在“。”之后、“，、；：”之后、文字与公式之间（已有空格，或与汉字相邻、排版会加空格之处）、`<person />` 之前断行，续行保持所在列表项、引用或脚注的缩进。不在这些地方断行：链接、公式、代码、标签之内，强调标记旁没有空格之处，会成为新块（列表、引用、标题等）的行首，行末反斜杠（硬换行）之后，标点之后紧接代码或图片之处（排版不会去掉那里的空白）。标题、表格、环境围栏、代码、注释和导言区不变；无法断到 100 列以内的行尽量短。预处理把行间公式的 TeX 去掉各行行首空白与首尾空白后再渲染，所以排版不改变 `data-tex` 与 TikZ 缓存。

缩进以 2 个空格为单位（与 YAML 和编辑器的 Tab 一致）。`npm run format` 统一列表：无序列表用 `-`，标记后一个空格，列表项的续行与项目的文字对齐（更深的缩进保留多出的部分，代码保留自己的缩进）（`- ` 之后 2 格，`1. ` 之后 3 格，`10. ` 之后 4 格，`(a) ` 之后 4 格，标签列表最多 14 格），嵌套列表写在上一层项目的文字处；公式内部的缩进每层 2 格。脚注的续行仍缩进 4 格。

本页描述已实现的共同格式，以百科默认编号为例。普通页面同样支持正文语法；指南和讲义的文件结构、整组引用与编号参数见 [章节说明](collections.md)。完整实例见 [奇异上同调](../tests/fixtures/content/wiki/奇异上同调/index.md)。

## 页面信息

```yaml
---
title: 奇异上同调
categories: [代数拓扑]
---
```

页面标题写在 `title` 中。修改时间由源文件最近一次 Git 提交的提交者日期生成，不能手动填写 `lastmod` 或 `gitLastmod`；尚未提交的文章不显示修改时间。正文不能使用一级 Markdown 标题：`# 标题` 和由 `===` 下划线组成的 Setext 一级标题都会导致构建报错。这个限制只适用于百科条目，不适用于首页等普通页面。

分类只需填写直接归属的分类，预处理会补齐祖先分类。类别关系在 `data/categories.yaml` 中维护。

中文正文在 postbuild 自动补中西文、中文与行内公式之间的普通空格，清理汉字之间、所有括号和引号内侧，以及全角括号和 `「」『』` 的中文外侧空白。弯引号 `‘’“”` 使用 Inter，汉字与上引号 `‘“`、下引号 `’”` 与汉字之间补普通空格，不检查引号配对，例如 `汉“字”汉` 变成 `汉 “字” 汉`。半角括号外侧与汉字之间补空格，例如 `如式(1.1)所示` 变成 `如式 (1.1) 所示`；半角逗号、句点等后紧随汉字时补空格，例如 `整数,实数` 变成 `整数, 实数`。NBSP 与其他所有特殊空格保留。中文句号 `。` 默认转换为实际字符 `．`，不改变小数和编号中的 ASCII `.`。可用以下文章参数只关闭句号转换：

```yaml
typography:
  convertChineseFullStop: false
```

标题和 wiki 链接文字也在 postbuild 执行空白排版，保留作者输入的半角或全角括号。`[[维数(向量空间)]]`、`[[维数 (向量空间)]]`、`[[维数（向量空间）]]` 都能匹配同一个条目，无需另设别名；查询时的名称归一化不改变显示括号。链接文字按 Markdown 排版显示（`--` 显示为 `–`，`---` 为 `—`，`...` 为 `…`），查询时目标也按同样方式读取，所以 `[[Auslander--Buchsbaum 公式]]` 链接到标题为 `Auslander–Buchsbaum 公式` 的条目；查询也不区分直引号与弯引号，`[[Guillaume de l'Hôpital]]` 与 `[[Guillaume de l’Hôpital]]` 相同。页面导言区的 `title` 和 `aliases` 也与正文一样做这些排版替换（公式除外，日语标题除外）：`title: l'Hôpital 法则` 显示为 l’Hôpital 法则，可以直接写 `'`；目录与网址不受影响。分类名称、`collection.yaml` 的 `title` 以及取自目录名的标题不做替换。连字符 `-` 与连接号 `–` 仍是不同的字符，需要时另设别名。公式内的括号、`f(x)` 等表达式和完整西文标题保持原样。中文引号默认使用 `“”`，构建不自动改写其他引号样式。

相邻标点至少有一个是中文标点时，也清理两者之间的普通空格和软换行，例如 `。 （` 变成 `．（`；NBSP 等特殊空格仍保留。术语翻译的分隔点自带视觉间距，排版不会跨过它再补空格。

中文语境中的全角标点与汉字、西文字母、数字、行内公式之间都清理普通空白，例如 `。 汉字` 变成 `．汉字`、`xxx （` 变成 `xxx（`、`， xxx` 变成 `，xxx`。半角逗号、句点、分号、冒号、感叹号和问号清理前面的普通空白，后接汉字时补一个空格，例如 `汉字 , 汉字` 变成 `汉字, 汉字`。所有特殊空格保留。

外文片段用 `<lang ko>한 글ABC</lang>` 等方式标注（含空行时为一个块，其中可以有几段）。英文、韩文区域保留原有空白；韩文启用原生 `text-autospace`。整篇外文文章可设置 `lang: ko` 或 `lang: en`。参考文献目前沿用西文排版，退出中文空白及句号转换。

百科主标题与分类名称支持普通文字和 `$…$`、`\(…\)` 行内公式；不展开其他 Markdown、链接或引用语法。独立公式、多行名称和未闭合的公式分隔符会导致构建报错。文章标题、列表、分类树、祖先导航和分类页脚保留公式显示，不自动大写字母；浏览器标签、分享标题和名称索引使用自动转换的纯文本名称（见下文“名称中的公式”），列表按下文的读音排序。讲义和指南中除首页外的页面，浏览器标签写作“页面标题 - 书册标题 - 香蕉空间”。标题与正文中的公式均在构建时渲染，关闭 JavaScript 也能显示。

在 wiki 条目的 `aliases` 中声明名称别名：

```yaml
title: '$\infty$-范畴'
aliases:
  - 无穷范畴
  - 无穷大范畴
categories:
  - '$p$ 进几何'
```

主标题和别名都按下文的公式转换规则、Unicode NFC 与首尾空白处理后匹配。同一条目内重复的名称自动去重；不同条目之间的主标题或别名冲突会导致构建失败，报错列出名称与源文件。改名后可将旧标题加入 `aliases`，页面路径继续由目录、`slug` 或 `url` 决定。

百科条目和讲义页面的网址默认取目录路径，保留大小写和标点，空格改为下划线，例如 `content/wiki/Riemann ζ 函数/` 的网址是 `/wiki/Riemann_ζ_函数/`。页面设置了 `url` 或 `slug` 时以其为准。其他页面使用 Hugo 的默认规则。

#### 名称中的公式

标题、别名、分类名称和 wiki 链接目标中的公式，由 KaTeX 渲染为 MathML 后转成线性文字（`scripts/shared/math-name.mjs`，与搜索索引共用 `math-text.mjs`）。同一个名称有两种形式：

| 用途 | 规则 | `$H^1(X;\mathbb Z)$ 的计算` |
| --- | --- | --- |
| 显示：浏览器标签、分享标题、书册标题、缺失条目的名称 | 线性文字，`\mathbb` 的常用字母（ℂ ℍ ℕ ℙ ℚ ℝ ℤ）写作对应字符 | `H^1(X; ℤ) 的计算` |
| 匹配：条目名与别名、链接目标、分类、标题锚点 | 显示形式再做 Unicode NFKC（ℤ 与 Z 相同），去掉公式内部的空白 | `H^1(X;Z) 的计算` |

上下标保留为 `^`、`_`，所以 `$L^p$` 和 `$L_p$` 是两个不同的名称。等价写法得到相同结果：`\mathbb Z` 与 `\mathbb{Z}`、`\operatorname{Hom}`、`\mathrm{Hom}` 与 `\text{Hom}`、`a_{2}` 与 `a_2`，以及公式内多写或少写的空格。直立字母的标准写法是 `\mathrm{…}`。简单情形下，链接也可直接写成匹配形式的纯文本，例如 `[[a_2 的性质]]` 链接到标题为 `$a_2$ 的性质` 的条目；复杂公式仍建议写 `$…$`。名称中的 TeX 有误（如未定义的命令）时，prebuild 报错并给出公式。

`[[无穷范畴]]` 直接链接到目标页，地址附带 `?from=无穷范畴`；目标页仅在来源匹配自身别名时显示“跳转自：无穷范畴”。关闭 JavaScript 时仍能到达目标页，但不显示来源提示。没有参与当前构建的草稿或未来发布条目，其主标题与别名都视为缺失。别名不额外生成文章或条目列表项。

项目不支持旧网址重定向。`aliases` 只用于百科条目的名称查询；普通 Markdown 链接按网址访问。

### 排序读音

条目、分类、讲义和指南页面都有一个读音，用于列表排序、将来的按字母分组，以及搜索中的拼音匹配。读音默认由标题自动生成：汉字按词语转换为不带声调的拼音，西文去掉变音符号后转为小写，希腊字母与 KaTeX 的希伯来字母（ℵ ℶ ℷ ℸ）写作字母名，其余符号忽略。例如：

| 标题 | 自动读音 |
| --- | --- |
| 奇异上同调 | `qi yi shang tong diao` |
| Künneth 公式 | `kunneth gong shi` |
| `$\infty$`-范畴 | `infinity fan chou` |
| `$E_8$` 格 | `e8 ge` |

自动读音不合适时，在 front matter 中用 `sort` 指定完整读音：

```yaml
title: Jean-Pierre Serre
sort: serre jean pierre
```

读音由小写字母和数字组成的词构成，词之间用一个空格分隔，不标声调；`ü` 写作 `v`（如 `lv`），也接受 `ü` 和 `u:`。大小写和多余空白会被规范化，其他字符导致构建报错。列表按首字母分组：标题以数字或符号（如 `2-范畴`、`$\infty$-范畴`）开头的条目归入 `#` 组并排在最前，其余按读音首字母归组；同一字母内西文开头的标题在前、汉字开头的在后，再按读音排序，读音相同时按标题排序。西文人名按姓氏排序时就需要手动指定，多音字通常不需要：

- 常见多音字由拼音库按词语判断，例如“调和”读 `tiao he`，“同调”读 `tong diao`。
- 拼音库读错的数学词语统一写进 `data/readings.yaml`，对所有标题生效，例如 `重数: chong shu` 也作用于“代数重数”。词表的键只含汉字，读音为每个字一个音节。

搜索同时收录手动读音、自动读音和别名的读音，以及它们连写和取首字母的形式，因此 `qi yi shang`、`qiyishang`、`qystd` 都能找到“奇异上同调”。分类在 `data/categories.yaml` 中用同名字段指定读音，讲义和指南的根页面也可在 `collection.yaml` 中设置 `sort`。

### 搜索

所有条目、讲义、指南页面和分类页默认进入站内搜索。在 front matter 中设置以下参数，可将页面排除在搜索之外：

```yaml
search: false
```

此参数只能设为 `false`，只影响搜索，页面仍出现在列表、分类和导航中。讲义或指南的根页面（或 `collection.yaml`）设置后，整组页面都不进入搜索。搜索的实现见 [docs/search.md](search.md)。

分类树也可使用带公式的名称：

```yaml
数学: {}
'$p$ 进几何':
  parent: 数学
```

分类关系与文章的 `categories` 都先转换成纯文本名称，再生成分类网址，例如 `$p$ 进几何` 的地址为 `/categories/p-进几何/`。分类显示采用分类树中的公式写法；未在树中声明的分类采用文章首次声明的写法。文章也可使用等价的纯文本名称引用分类。树中两个分类转换成同一名称时构建报错；原始名称中的 TeX 反斜杠允许使用，转换后的名称仍不能包含路径分隔符。

## 节标题与目录

```markdown
## 定义 {@sec:definition}

### 系数的选择 {@sec:coefficients}

## 参考文献* {@sec:references}

## 字面星号\* {@sec:literal-star}
```

- 二级标题默认按文中出现顺序编号为 `1`、`2`、`3`。
- 标题末尾的 `*` 表示不编号，推荐紧贴标题写成 `## 参考文献*`，也可写为有空格的 `## 参考文献 *`。星号可以写在属性之前或整行末尾：`## 参考文献* {@sec:references}` 与 `## 参考文献 {@sec:references}*` 等价。
- 不编号节仍出现在目录中，有正常锚点，但不占用节号，也不重置定理和公式计数器。后续编号接续最近的编号节；首个编号节之前使用整数编号。
- 想让标题显示结尾星号时写 `\*`；例如 `## 字面星号\*` 仍是编号节，显示文字以 `*` 结尾。`*斜体*`、`**强调**` 的闭合星号，以及行内代码和公式中的星号不作为不编号标记；强调标题若不编号，可写成 `## **强调***`。
- 三级到六级标题不编号。
- 文章自动生成二级、三级标题的目录，目录与正文使用相同编号和锚点，不需要 shortcode。宽屏在右侧显示并高亮当前节；窄屏在第一个正文标题前显示折叠入口，入口滚出视野后可从顶栏打开目录。
- 少于两个目录项的页面默认隐藏目录。可在 front matter 中设置 `toc: false` 关闭某页目录；`tocDepth` 可设置显示的标题层数（从二级标题起，默认 2，允许 0 至 5）。目录自动生成，不支持手写 `toc` shortcode。
- 二级标题也可用 Setext 的 `---` 下划线形式书写；不编号星号写在标题文字行末，例如 `参考文献*` 下一行接 `---`。
- `{@标签}` 是可选的引用标签，不作为标题的 HTML `id`。标题锚点由 prebuild 按标题文字生成，再交给 Hugo 的正文和目录共同使用；例如 `## 定义 {@sec:definition}` 的 `id` 是 `定义`，`@sec:definition` 会跳转到 `#定义`。
- 修改标签不会改变标题锚点；重复 ID 由 prebuild 添加 `-1`、`-2` 等后缀区分。标签用于维持文内引用，改标题时无需改引用语法。
- 编号不参与自动锚点计算，插入前面的节不会仅因编号改变而改变既有锚点。

节标题和自定义环境使用正文层级，前面可有零到三个空格。不要把节标题放在列表或引用块中。定理环境内不能开始新的二级节；三级及以后的小标题可以使用。

标题 ID 的规则集中在 `scripts/prebuild/structure.mjs` 的 `headingId()`，可在这里自定义。默认先提取链接的显示文字、将公式转为上述匹配形式，并按共同排版规则补/清理空白，再去除 diacritic（音符）、将 en dash `–` 改为 hyphen `-`。字母转为小写，空白转为 `-`，去掉格式标点，保留中文、数字及数学符号。例如：

| 标题文字 | 基础 ID |
| --- | --- |
| `Über` | `uber` |
| `Poincaré–Lefschetz` | `poincare-lefschetz` |
| `$\infty$-范畴` | `∞-范畴` |
| `$A \otimes B$` | `a⊗b` |
| `$H^1$ 的计算`、`$H_1$ 的计算` | `h1-的计算`、`h_1-的计算` |
| `中文API与$f$` | `中文-api-与-f` |
| `汉 字` | `汉字` |

合成形式的 `ü` 和分解形式的 `u` 加组合音符产生相同基础 ID。转换后为空时使用 `heading`；后缀检查针对整篇文章已使用的 ID，因此去音符等转换造成的碰撞也会被区分。显示标题保留公式和格式并执行共同排版规则，节编号不参与 ID 计算。

## 定理类环境

```markdown
::: theorem [万有系数定理] {@thm:uct}
设 $X$ 是拓扑空间，$A$ 是 Abel 群，则……

正文支持 **强调**、列表、[[内部链接]]、公式和代码块。
:::
```

形式为 `::: 类型 [标题] {@标签}`，标题和标签都可省略，顺序固定：

```markdown
::: definition
定义正文。
:::

::: lemma {@lem:key}
引理正文。
:::

::: remark [关于系数]
注的正文。
:::
```

| 类型 | 显示名称 | 边框 CSS 类 | 左边框及标题颜色 |
| --- | --- | --- | --- |
| `definition` | 定义 | `theorem-definition` | 橙色 |
| `theorem` | 定理 | `theorem-theorem` | 蓝色 |
| `lemma` | 引理 | `theorem-theorem` | 蓝色 |
| `proposition` | 命题 | `theorem-theorem` | 蓝色 |
| `corollary` | 推论 | `theorem-theorem` | 蓝色 |
| `example` | 例 | `theorem-example` | 紫色 |
| `remark` | 注 | `theorem-remark` | 绿色 |
| `notation` | 记号 | `theorem-definition` | 橙色 |
| `conjecture` | 猜想 | `theorem-theorem` | 蓝色 |
| `exercise` | 习题 | `theorem-example` | 紫色 |
| `convention` | 约定（不编号） | `theorem-remark` | 绿色 |

所有编号定理类环境共用一个计数器。例如第一节依次出现定义、定理、注，显示为“定义 1.1”“定理 1.2”“注 1.3”。新编号二级节重置节内计数；首个编号节之前的环境编号为 `1`、`2`，例如“定理 1”。没有编号节的文章始终使用整数编号。没有标签的环境同样参与编号。

在类型后加 `*` 创建不编号环境，标题、颜色和正文排版保持一致，并且不占用计数器：

```markdown
::: theorem* [存在性] {@thm:existence}
定理正文。
:::

::: definition*
不编号的定义。
:::
```

所有表中的类型均可使用星号形式，如 `lemma*`、`example*`。

类型前加 `-` 创建只显示标题的环境：框的样式按类型决定，标题只显示方括号中的文字，不显示类型名和编号，也不占用计数器。适合讲义中“寄语”“回忆”“警告”这类自成一类的段落：

```markdown
::: -remark [寄语]
正文。
:::
```

这种写法必须有标题，不能与 `*` 同用，也不能用于 `proof`。引用 `@标签` 时显示标题文字。

所有表中的类型均可使用星号形式，如 `lemma*`、`example*`。`@thm:existence` 默认显示“定理 (存在性)”并跳转到该环境；无标题时只显示环境名。标题支持强调、行内公式和链接，自定义引用仍可写成 `[这个定理](@thm:existence)`。`proof` 默认不编号。

标题支持行内公式、强调和链接。标题必须在一行内；需要字面方括号时可以使用实体，例如 `[关于 &#91;a,b&#93; 的注]`。含 TeX 时遵循下文的公式分隔符规则。

围栏需独占一行；结束围栏的冒号数量须与对应开始围栏一致。定理类环境可以嵌套，结束围栏关闭最近一个未关闭的环境；证明必须独立书写，不得嵌套在定理内部，也不能包含定理环境。

## 证明

```markdown
::: theorem [基本性质] {@thm:basic}
定理正文。
:::

::: proof
证明正文。
:::
```

`proof` 显示“证明”，末尾显示 `□`，不编号，也不改变定理计数器。放在定理环境结束之后，不能嵌套在定理内部。证明无边框，标题与首段正文同行，中文标题后使用一个 U+3000 全角空格（1em）；末尾 `□` 跟随最后一段正文，不另起一行。可选标题写成 `::: proof [另一种证明]`，标题代替“证明”二字显示，例如 `::: proof [@thm:main 的证明]` 显示“定理 1.2 的证明”；标题因此应是完整的说法，如“证明概要”“证明（构造）”。若设置标签，默认引用文字为标题，没有标题时为“证明”。

## 环境配置与翻译

环境类型在 `data/theorems.yaml` 中配置，每项指定 `group`（颜色组）。显示名称的 i18n 键由环境类型自动生成，例如 `theorem` 使用 `environment_theorem`。可选的 `numbered` 控制是否参与统一编号，默认为 `true`；不编号的环境需设置 `numbered: false`。例如：

```yaml
theorem:
  group: theorem
```

中文显示名称在 `i18n/zh-cn.yaml` 中定义。名称可以使用 `{{ .Number }}`，例如 `定理{{ with .Number }} {{ . }}{{ end }}`。增加语言时在对应 i18n 文件中提供这些键即可；定理标题和默认引用在 Hugo 渲染时使用页面语言，不在预处理时固定成中文。

`environment_title` 控制标题括号（也用于有标题的不编号环境引用），`proof_heading` 控制证明标题，`proof_title_separator` 控制标题与正文间的分隔空白（其他语言可设为空字符串），`reference_section`、`reference_equation`、`reference_item` 控制节、公式与列表项目的默认引用文字。自定义引用文字仍按作者填写的内容显示。

四组定理只保留左边框，标题使用对应着重色。证明无边框。

## 自动编号公式

````markdown
```math {@eq:boundary}
d^{n+1} \circ d^n = 0
```
````

`math` 块的正文是原始 TeX，不再包裹 `$` 或 `\[`。标签可省略。使用三个或更多反引号，也可使用波浪号围栏。开始和结束围栏使用同一种字符，结束长度不得短于开始长度。

每个 `math` 块获得一个公式编号。公式计数器独立于定理计数器，按编号二级节重置；首个编号节之前使用 `(1)`、`(2)`，进入第一节后重新从 `(1.1)` 开始。没有编号节的文章始终使用整数编号。不编号节不重置公式计数器。预处理插入对应的 `\tag{编号}`，由 KaTeX 显示括号编号。

多行公式在一个块中使用 `aligned`，共用一个编号：

````markdown
```math {@eq:calculation}
\begin{aligned}
a &= b + c \\
  &= d.
\end{aligned}
```
````

自动编号块内不能手写 `\tag` 或 `\tag*`。逐行自动编号暂不支持。普通 `$…$`、`$$…$$`、`\(...\)`、`\[…\]` 仍可使用，它们不自动编号，原有的手工 `\tag` 保持有效。

## 交换图与 TikZ 图形

含 `tikzcd` 或 `tikzpicture` 的公式在构建时编译成内联 SVG，支持中文和文字选择；多个图表及外层 `\left/\right` 由真实 TeX 排版。独立 TikZ 图形使用 `tikz` 代码围栏，图居中；说明写成 ` ```tikz {caption="说明"} `，显示在图下。完整写法与中文适配限制见 [TikZ 说明](tikz.md)。

## 有序列表项目

将标签写在数字列表标记之后、项目正文之前：

```markdown
1. {@item:condition-a} 条件 A。
1. {@item:condition-b} 条件 B。
   1. {@item:subcondition} 子条件。

由 @item:condition-b 和 @item:subcondition 可知……
也可以写 [第二个条件](@item:condition-b)。
```

默认引用文字分别为“2”和“2.1”。标签可省略，未设置标签的项目也计入顺序；标签随项目移动后，引用编号自动更新，跳转锚点保持不变。

项目编号来自 Markdown 列表结构，不是逐行照抄源码数字。例如 `3.` 开始的列表随后写 `1.` 或 `9.`，第二项的实际编号仍为 `4`，引用显示“第 4 项”。支持 `1.` 和 `1)` 标记、非 1 起始、紧凑/含多段落的列表、引用块内的列表和嵌套列表。嵌套引用串联有序祖先编号；无序祖先不加入编号路径。列表重新开始时重新使用该列表的起始编号，与节号、定理号无关。

标签必须与数字标记位于同一行，紧接标记后的空白，例如 `1. {@item:key} 内容`；标签后须有空白或换行。项目正文中其他位置的 `{@标签}` 是普通引用。无序列表不声明编号项目。代码、公式和注释里的列表语法不创建目标。

预处理使用 CommonMark 解析树计算列表起始值、兄弟顺序与嵌套关系，Hugo 负责实际列表渲染；引用在构建时完成，不依赖浏览器 JavaScript。项目标签输出为项目开头的锚点。

## 标签列表

以 `(标签)` 或 `标签)` 开头的行是标签列表的项目，标签照写的样子显示，不自动编号：

```markdown
(a) {@item:first} 第一个条件。
(b) 第二个条件。
    续行与项目文字对齐。

(T2') 撇号写作 `'`，显示为 ′。
($\ast$) 其他标签写成一个公式。

1. 外层

   (i) {@item:inner} 内层（新的标签列表前须空一行）
```

- 标签由字母、数字组成，后面可有撇号：`(a)`、`(iii)`、`(A1)`、`(2')`；不带左括号时不能只有数字（`1)` 是 CommonMark 的有序列表）：`a)`、`iv)`、`A1)`、`1')`。其他标签写成括号中的一个公式（`$…$` 或 `\(…\)`，公式内可有空格）：`($\ast$)`、`($T_{2\frac12}$)`。标记后须有空白或行尾。`'` 显示为 `′`。不支持 `a.`、`i.` 这样以句点结尾的标签。
- 新的标签列表不能打断段落：第一项前须空一行，或位于块的开头（如 `::: theorem` 之后）；同一列表的后续项目可以紧接上一项。段落中恰好以 `(3) ` 开头的续行仍是正文。行首的 `(1)` 等不是列表时，在右括号前加反斜杠：`(1\) 与 (3) 之间的对应`（CommonMark 对 `1\)` 也是如此；单独的 `\)` 不是公式分隔符）。
- 项目的文字列是标记后的文字所在的列（`(a) ` 之后 4 格，`(iii) ` 之后 6 格），最多 14 格：续行、后续段落和嵌套列表缩进到这一列。标记后有 5 个以上空格时，与 CommonMark 相同，项目以缩进代码开始。
- 标签列表与编号列表（`1.`、`1)`）是不同的列表；标签项目紧接编号项目而成为同一列表时，预处理改用另一种分隔符将两者分开，仍无法分开时报错。
- 引用文字：只有编号项目的路径显示为编号，如“2.1”（`reference_item`）；含标签项目时，各层写作 `(a)`（括号标签）或 `a`（不带括号的标签去掉 `)`）、编号层写作数字，以空格连接，例如 `(a)`、`2 (a)`、`(2) i`。`@-标签` 对标签项目同样显示这些文字。

实现：预处理（`scripts/prebuild/lists.mjs`）在 CommonMark 投影中把标签标记写成同样文字列的有序列表标记 `0)`、`00) ` 等（起始值不是 1，因此新列表不能打断段落），解析出的项目在交给 Hugo 的 Markdown 中同样替换，标签由 `_item-label` shortcode 输出在项目开头（`<span class="item-label">`），样式隐藏列表序号并把标签右对齐到原来序号的位置。标记的语法在 `scripts/shared/scan.mjs` 的 `labelledMarkerSource`，编辑器的语法（`scripts/shared/markdown-language.mjs` 的 `labelledList`）按同样的规则读取。

## 标签与统一引用

标题、定理环境、自动编号公式和有序列表项目用 `{@标签}` 声明引用目标：

````markdown
## 定义 {@sec:definition}

::: theorem [万有系数定理] {@thm:uct}
定理正文。
:::

```math {@eq:boundary}
d^{n+1} \circ d^n = 0
```

由 @thm:uct 可知……
参见 @sec:definition。
结合 @eq:boundary，得到……
也可以写 [上述定理](@thm:uct)。
````

推荐在裸 `@标签` 前后加空格。末尾的 `,.;:'"!?` 以及中文标点不属于标签，会保留在正文中；例如 `@thm:uct,` 只引用 `thm:uct`。标点可以出现在标签中间，特别是 `:`，因此裸引用后若紧接正文，仍需用空格分隔。

需要明确边界时写 `{@标签}`，例如 `由{@thm:uct}可知`。这是正文中的单个引用，不添加括号。标题或定理/公式围栏末尾，以及有序列表项目开头的 `{@标签}` 则是目标声明；若要在标题末尾显示引用，可使用 `[@标签]`。

| 目标 | 默认引用文字示例 |
| --- | --- |
| 定理、定义等 | `定理 1.2`、`定义 1.1`、`注 1.3` |
| 不编号定理环境 | `定理 (存在性)`；无标题时为 `定理` |
| 编号二级标题 | `第 1 节` |
| 不编号二级标题 | 标题文字 |
| 三级及以后标题 | 标题文字 |
| 自动编号公式 | 按 `reference_equation` 翻译，当前中文为 `(1.1)` |
| 有序列表项目 | `2`、`2.1` |
| 标签列表项目 | `(a)`、`2 (a)`、`(2) i` |
| 证明 | `证明` |
| 文献 | `Serre 1955`、`nLab a` |

`[显示文字](@标签)` 自定义引用文字，支持强调和行内公式。`@-标签` 只显示编号，用于名称已写在正文中的情形，如 `第一同构定理（@-thm:first-iso）` 显示为“第一同构定理（1.2）”；目标没有编号（文献、不编号的环境）时报错。所有引用都链接到具体目标，支持前向引用。

方括号表示引用组；分号分隔目标，逗号后填写该项的附注：

```markdown
[@serre]
[@serre, 第 3 章]
[@serre, 定理 2.1; @other, §4]
[@thm:uct; @eq:boundary]
```

引用组总是显示外层方括号，裸引用和 `{@标签}` 不显示括号。附注保留作者填写的文字，不猜测或改写页码、定理号；支持强调、行内公式和普通链接。逗号后推荐加空格，以区分附注与包含逗号的标签；复杂标签也可以在组内用完整形式，如 `[{@a,b}, 附注]`。

结构标签和文献 key 共用整篇文章的命名空间，必须唯一，不同文章可以重用；指南和讲义则共用整组页面的命名空间。名称按 Unicode NFC 规范化，可用中文和内部标点；不得含空白、`#@{}<>[]|`、括号、反斜杠和反引号，也不得以标点结尾；裸引用末尾的 `,.;:'"!?`、连接号 `–—` 和连字符 `-` 属于正文，标签在其前结束，因此可以写 `式 @eq:a–@eq:b`；标签名也不能以这些符号结尾。建议结构目标使用 `sec:`、`thm:`、`def:`、`eq:`、`item:` 前缀，文献可使用 `bib:`；前缀不决定目标类型。

重复标签、缺失引用目标、无效标签和锚点冲突都会使构建失败，错误包含源文件和行号。标题标签仅用于查找，实际 HTML ID 仍按标题计算；定理/公式/列表项目标签作为实际 ID，文献使用 `bib-标签` 作为实际 ID。

`[[页面@标签]]` 保留给未来的跨页面对象/文献引用，当前明确报错，不会作为缺失百科条目处理。跨页普通链接使用 Markdown 链接。

引用在 Markdown 正文（包括脚注 `[^1]: …` 的内容）中解析，不在 TeX 内展开；邮箱、普通 Markdown 链接文字及地址、代码、HTML 注释和标签的参数保持原样。字面语法可写 `\@标签`、`\{@标签}` 或 `\[@标签]`，也可使用行内代码。

## 参考文献

参考文献数据放在 `bibliography` 围栏中，在原位置生成 Markdown 无序列表，不自动插入标题。一个页面可以有多个块，块之间直接写普通 Markdown 简介。每个块保留文献的声明顺序，全文先收集所有文献，再解析引用和计算消歧后缀。

````markdown
## 参考文献

```bibliography
serre:
  type: book
  author: Jean-Pierre Serre
  title: 某本书的标题
  year: 1955
  publisher: 某出版社
```

这本书的简介可以包含公式 $A$、[[百科链接]] 和其他引用。

```bibliography
nlab:a:
  type: online
  site: nLab
  title: Sheaf
  url: https://ncatlab.org/nlab/show/sheaf
nlab:b:
  type: online
  site: nLab
  title: Cohomology
  url: https://ncatlab.org/nlab/show/cohomology
```

这两个来源的正文引用分别为 @nlab:a 和 @nlab:b。
````

| 类型 | 用途 | 主要附加字段 |
| --- | --- | --- |
| `book` | 专著 | `publisher`、`location`、`edition`、`series`、`volume` |
| `article` | 已发表期刊文章 | `journaltitle`、`volume`、`number`、`pages` |
| `incollection` | 书或文集中的文章 | `booktitle`、`editor`、`publisher`、`pages`、`series`、`volume` |
| `thesis` | 学位论文 | `institution`、`degree`（`phd`、`master` 或其他文字，显示为 PhD thesis 等）、`location` |
| `preprint` | 未发表预印本 | `arxiv`、`url` |
| `online` | 在线百科、问答、网页等 | `site`、`url`、`author`、`urldate` |

每项必须有 `type` 和 `title`，在线资料还必须有 `site` 和完整的 HTTP(S) `url`。其他字段按已知信息填写，不强制补齐全部出版数据。共同字段包括 `author`、`editor`、`year`、`doi`、`arxiv`、`zbmath`、`url`、`shorttitle`、`howpublished`、`note`、`label`。未知字段报错，避免拼写错误悄悄丢失数据。

`year` 是四位年份，不能手写 `2020a`；`urldate` 使用带引号的 `YYYY-MM-DD`。DOI、arXiv 和 zbMATH 字段只填标识符，程序生成链接；老式 arXiv 标识符如 `q-alg/9706008` 同样支持。数字标识符建议加引号以保留前导零。数据字段按文字排版，不展开字段内的 Markdown、HTML、shortcode 或引用语法，但行内公式（如 `title: '$\infty$-Categories in Topology'`）照常渲染；需要丰富的介绍时写在文献块外。

作者和编者支持字符串、姓名对象以及它们的列表：

```yaml
author: Jean-Pierre Serre
# 等价于：
author: "Serre, Jean-Pierre"
# 也可以明确指定：
author: {family: Serre, given: Jean-Pierre}

# 多人时使用列表；字符串含逗号时要加引号：
author: ["Frenkel, Edward", David Ben-Zvi]

# 中文字符串整体保留，正文引用也显示全名：
author: 张三

# 机构或复杂姓名可以明确要求整体保留：
author: {literal: A research group}
```

西文姓名中有逗号时按 `Family, First` 拆分；没有逗号时，最后一个词作为姓，其余作为名。多词姓等复杂情况使用逗号格式或对象，不依赖自动猜测。含汉字的字符串整体保留；`editor` 使用同样的规则。以上 YAML 示例是分别可选的写法，不要在同一条文献里重复声明 `author`。

默认正文显示一位作者的姓（或整体姓名）、两位作者的姓，三位及以上显示第一位加 `等`；没有作者时尝试编者，再回退到 `shorttitle` 或 `title`。文献列表显示完整姓名，只加粗姓氏及其后的逗号，名字保持普通字体；中文全名、整体姓名和站点名整体加粗。书名、期刊名和文集名使用斜体。DOI、arXiv、zbMATH 和普通资料链接各自带括号，中间用空格分隔。

发表文献显示年份；缺失年份时显示“无日期”。`preprint` 不显示年份或额外的 preprint 字样，即使数据中保留了 `year`。已发表的 `article` 可以同时有 arXiv 链接，仍显示发表年份。

`online` 的默认引用作者始终是 `site`，不是页面标题或实际贡献者。实际作者可保存在 `author` 中并在列表中显示。在线资料的 `year` 可作为元数据保留，但默认不用于引用的日期位置；访问日期也不当作发表年份。

同页中默认引用作者和日期相同的文献自动加 `a`、`b`、`c`……，超过 `z` 后使用 `aa`、`ab`。后缀按全文声明顺序分配，包括未被引用的文献，并跨所有文献块计算。正文与文献列表一致：

| 情况 | 正文 | 文献列表的作者日期部分 |
| --- | --- | --- |
| 同作者同年份 | `Smith 2020a`、`Smith 2020b` | `**Smith,** Alice (2020a)`、`**Smith,** Alice (2020b)` |
| 单个在线来源 | `nLab` | `nLab` |
| 同站点多个来源 | `nLab a`、`nLab b` | `nLab (a)`、`nLab (b)` |
| 同作者多篇 preprint | `Sella a`、`Sella b` | `**Sella,** Yehonatan (a)`、`**Sella,** Yehonatan (b)` |

可以用 `label: "EGA I"` 覆盖正文引用文字，程序不再附加作者与年份。文献列表在作者之前显示 `[**EGA I**]`，后面仍保留正常的作者与出版信息。多个文献使用同一个显式 label 时，按声明顺序显示 `EGA I a`、`EGA I b`，条目前缀同步显示相同后缀。

标题中的引用在正文和目录里使用相同的渲染结果。目录与自定义引用文字只保留内层引用的显示文字，避免嵌套链接；未编号标题之间若形成显示文字的循环引用，构建会明确报错。

页内锚点跳转统一避开顶部导航栏。`site.js` 根据导航栏实际高度设置滚动偏移，CSS 提供平滑滚动；系统设置“减少动态效果”时关闭动画。直接打开带 fragment 的 URL 也会在页面加载完成后重新校准。

默认排版策略集中在 `scripts/prebuild/bibliography.mjs` 的 `citationPolicy` 与 `bibliographyFormats`。构建副本保留规范化后的 `bibliographyEntries` 元数据，正文文献链接带 `data-reference`，为以后更换模板或增加读者偏好留出接口；当前尚未实现运行时样式切换和完整 BibLaTeX 导入。

## 百科链接与普通链接

```markdown
[[顶点代数]]
[[对偶模|对偶 $A$-模]]
[[$\infty$-范畴]]
[外部文献](https://example.com/paper)
```

`[[条目名]]` 按百科文章的 `title` 或 `aliases` 查找目标，`[[条目名|文字]]` 自定义显示文字；表格中可把竖线写成转义的 `[[条目名\|文字]]`。目标可含公式；用于匹配时常见 TeX 符号转为 Unicode。匹配区分大小写。通过别名进入时显示来源提示。未创建的条目显示为红色链接，点击进入缺失条目提示页。普通 Markdown 链接的目标地址保持原样。

节首可用 `<see>` 标签指向相关条目，显示为“参见：……”：

```markdown
<see>[[Galois 理论]]、[[Galois 上同调]]</see>
```

内容为行内 Markdown，不接受参数。

图片使用 Markdown 语法，图片文件放在页面包内。地址可带 `?width=像素` 指定显示宽度，例如 `![正一百二十胞体](120-cell.png?width=200)`；宽度不超过正文宽度。单独成段的图片居中显示，方括号中的说明文字（可含公式和链接）显示在图下；与文字同段的图片保持行内。方括号中的说明同时作为图片的替代文字。只需要替代文字、不在图下显示说明时，方括号留空，替代文字写成标题：`![](图.png?width=400 "替代文字")`。

## 数学、转义与代码保护

公式内部的 TeX 原样保留，不为 Markdown 再次转义。例如 `aligned` 中的换行写成 `\\`。公式解析跟踪花括号和 TeX 注释，支持 `$a \text{$b$} c$` 这样的内层美元符号。

引用块中的多行公式，每行照常写引用标记 `> `；与起始行同深度的标记属于引用块，不进入 TeX。公式中不能有空行，空行会结束段落。

几个特殊字形：`\mathbb{1}` 显示为 𝟙（交换图中也是），没有双线字形的 `\mathbb{\Delta}` 等希腊字母显示为粗体；镜像字母 `ꓘ`（U+A4D8）、`ꓷ`（U+A4F7）显示为左右翻转的 K、D，例如 `\mathrm{ꓘꓷ}` 是镜像的 DK，在普通公式和交换图中都可使用。交换图中的 `\mathscr` 与普通公式用同一套字形。网站不允许 `\htmlStyle`、`\href` 等 KaTeX 扩展命令。

公式不跨空行：`$…$`、`\(…\)`、`\[…\]` 到段落结束还没有闭合时报错，错误指向公式的起始处；否则一个多余的 `{` 或没有闭合的 `\[` 会让公式吞掉之后的段落，报出无关的错误。`$$` 同样。行内代码也在段落结束处结束（与 Markdown 相同）。空的公式（`\[\]`、`$$$$`、`$ $`）不输出任何内容。同理，没有 `-->` 的注释、到段落结束还没有 `>}}` 的短代码标记、没有结束围栏的代码块都报错，而不是一直保护到页面末尾。正文中的普通美元符号写成 `\$`，普通反斜杠写成 `\\`。因为 `\[` 是公式起始分隔符，若需方括号包围 Markdown 链接，应写成 `&#91;[文字](地址)&#93;`。

普通代码块、行内代码、HTML 注释、标签的参数、Markdown 链接的地址和引用式链接定义不进行编号或引用转换。代码块中的 `::: theorem` 和 `@标签` 只是代码。

署名、日期、引文出处等需要居右的文字使用 `<align right>…</align>`，居中的文字用 `<align center>`；内容按块级 Markdown 渲染，各行之间用行末反斜杠换行，例如

```markdown
<align right>
——R. Bott，杜武亮\
*Differential Forms in Algebraic Topology*
</align>
```

单独成段的图片、TikZ 图和独立公式已经居中，不需要 `align`。折叠内容使用 `<spoiler title="标题">…</spoiler>`（内容为块级 Markdown）；定理、定义及证明统一使用 `:::` 环境。`@@math:…:math@@`、`@@displaymath:…:displaymath@@`、`@@numberedmath:…:numberedmath@@`、`data-section-number`、`data-section-unnumbered` 保留给生成流程使用，不要手工填写。

### 标签与 shortcode

Markdown 写不出的几种内容用标签：`<see>…</see>`、`<lang 语言>…</lang>`、`<align right|center>…</align>`、`<spoiler title="…">…</spoiler>`，以及写在姓名之后、单独使用的 `<person … />`（也可不写 `/`）。标签写在一行之内，参数写成 `名称="值"`（`lang` 与 `align` 的参数直接写值）。预处理（`scripts/prebuild/tags.mjs`）检查后把它们换成同名的 Hugo shortcode（`layouts/shortcodes/`），页面本身不含 shortcode：

- 源文件的任何位置（正文、代码、注释、front matter）都不能出现 shortcode 的开头（两个左大括号后接 `<` 或 `%`），因为 Hugo 在代码块中、在模板交给 `RenderString`/`markdownify` 的字符串中同样执行 shortcode。字面的大括号写成 `\{`。生成的页面在交给 Hugo 之前再检查一遍：front matter 的所有字符串（YAML 解析之后，`\x7B` 这样的转义也算）中没有 shortcode，正文中只有本站模板中的 shortcode。
- 名称以 `_` 开头的 shortcode（`_theorem-start`、`_item-target`、`_bibliography-start` 等）只由预处理写出，没有对应的标签（标签名以字母开头）；其余的必须正好是作者的标签，构建开始时核对（新增模板要么在 `tags.mjs` 中给出标签与参数，要么以 `_` 开头）。
- 参数逐个检查：未知或重复的参数、缺少的必填参数、错误的语言代码、`align` 以外的方向都报错；值不能含有引号、反斜杠、大括号、换行、控制字符，不超过 300 字，除人名的 `original` 中表示读音的 `<かな>` 外不能含有 `<`、`>`。模板输出时另行转义，`lang` 也再检查一次语言代码。
- 成对的标签必须配对：没有结束、没有开始或交错的标签报错。
- 其他 HTML 标签（`<span>`、`<script>`、`<img>`、`<pre>` 等，包括跨行写的）都报错；Hugo 本来也不输出原始 HTML。正文中字面的 `<` 后面紧跟字母并构成标签的样子时，写成 `&lt;`，或放进公式、代码。自动链接 `<https://…>` 照常使用。

链接与图片的地址只能是站内地址或 http、https（链接还可以是 mailto），`javascript:`、`data:` 等报错。front matter 的 `url`、`slug` 必须是站内地址：不含空白、引号、尖括号、`\`、`?`、`#`、`.`/`..` 段或 `//`。

## 页面提示与学科导航

百科条目的 front matter 可声明顶部提示与底部导航，参数直接与 `name` 并列：

```yaml
notices:
  - name: 问题
    items:
      - 第 2 节的命题缺少证明。
      - 缺少例子。
  - name: 消歧义
    about: 代数拓扑中的上同调
    see:
      - topic: 层的上同调
        page: 层上同调
navboxes: [代数拓扑]
```

没有需要填写的参数时，提示可直接写名称，如 `notices: [名称]`。多个组件按声明顺序显示。提示位于页面标题之后、导言之前；导航位于正文之后、分类与最后修改时间之前。二者不参与文章目录、节号、定理编号或页内引用。实例见 [组件示例](../tests/fixtures/content/wiki/components-example/index.md)。

现有的提示：

| 提示 | 参数 | 显示 |
| --- | --- | --- |
| `问题` | `items`：问题列表，必填 | “本条目存在以下问题：”及问题列表 |
| `消歧义` | `about`：本条目介绍的含义，可省略；`see`：列表，每项含 `page`（条目标题，或标题的列表，必填）和 `topic`（这些条目的含义，省略时为“其他含义”） | “本条目介绍的是……。关于……，请参见……。” |
| `区分` | `pages`：条目标题列表；或 `text`：整句文字 | “注意与……、……区分。” |
| `提示` | `text`：必填 | 文字本身 |

提示在 `content/notices/名称.md` 中维护，无需再声明类型。例如 `content/notices/消歧义.md`：

```markdown
---
style: info
icon: disambiguation
parameters:
  about: {}
  see:
    type: list
    required: true
    fields:
      topic: {}
      page:
        type: list
        required: true
---
{{{#about}}}{{{本页}}}介绍的是{{{about}}}。{{{/about}}}{{{#see}}}关于{{{#topic}}}{{{topic}}}{{{/topic}}}{{{^topic}}}其他含义{{{/topic}}}，请参见 {{{#page|、}}}[[{{{.}}}]]{{{/page}}}。{{{/see}}}
```

`style` 可为 `info`（默认）、`warning`、`error` 或 `note`；可选 `title` 显示提示标题，`icon` 可选 `disambiguation`（分支箭头）、`tip`（信息符号）或 `problem`（警告三角形）。`name` 保留给提示名称。

参数配置接受 `required`、`default`、`type` 和 `fields`：

- `type: text`（默认）：单行文字，支持行内 Markdown、百科链接和公式；可设 `default`。
- `type: list`：非空列表。没有 `fields` 时每项是单行文字；有 `fields` 时每项是字段到值的映射，`fields` 列出允许的字段，每个字段可设 `required`（是否必填）和 `type`：`text`（默认）为单行文字；`list` 为单行文字的非空列表，也可只写一个文字，视为一项，例如 `page: 并集` 与 `page: [并集, 交集]`。列表参数不能设 `default`。

正文和标题使用简单的模板：

- `{{{参数}}}` 替换为文字参数，未提供的非必填参数为空文字。
- 内置值 `{{{本页}}}` 在百科条目中为“本条目”，在讲义、指南等其他页面中为“本页面”，例如 `{{{本页}}}存在以下问题：`。
- `{{{#参数}}}…{{{/参数}}}`：对列表逐项重复其中内容，项为文字时用 `{{{.}}}` 引用，项为映射时直接用字段名；对文字参数，非空时出现一次。写成 `{{{#参数|分隔}}}` 时在各项之间插入分隔文字。
- `{{{^参数}}}…{{{/参数}}}`：参数为空或未提供时出现。
- 开始标记后紧跟的换行不计入，便于逐行写 Markdown 列表。

未知参数或字段、缺少必填参数或字段、类型不符、引用未声明参数或文件不存在都会导致构建失败。

`content/notices/` 与 `content/navboxes/` 是组件定义目录，prebuild 单独读取它们，不复制到 `.build/content/`，也不生成普通页面或作为附件发布。仅源内容根目录下的这两个目录有此特殊用途；页面包里的同名附件目录仍按原样复制。

导航在 `content/navboxes/名称.yaml` 中维护。例如：

```yaml
title: [[代数拓扑]]
groups:
  - title: 同调论
    subgroups:
      - title: 同调
        items:
          - [[奇异同调]]
          - [[胞腔同调]]
      - title: 上同调
        items:
          - [[奇异上同调]]
          - [[de Rham 上同调]]
  - title: 同伦论
    items:
      - [[基本群]]
      - [[同伦群]]
```

每个分组填写 `title`，并在 `items` 与 `subgroups` 中选择一个非空列表。分组最多四层。程序按树自动计算 `rowspan` 和 `colspan`，输出 HTML 导航表，不使用 Markdown 管道表格。标题与项目支持行内 Markdown、百科链接和公式。项目使用淡色细竖线分隔，允许换行。默认展开，文件顶层设置 `collapsed: true` 可默认收起；通过标题栏右侧的“展开／收起”切换，无需 JavaScript。直接指向当前条目的链接会显示为黑色加粗文字，并保留自定义显示文字和公式；其他链接及正文链接不受影响，兼容自定义页面地址与站点子路径。

导航的标题、分组标题和项目允许整项裸写 `[[条目]]` 或 `[[条目|文字]]`。这是这些内容字段的扩展：程序读取 YAML 节点保留的完整源文字，仅识别整项百科链接，不将任意嵌套列表还原成文字。与其他文字混排时仍使用字符串，如 `"参见 [[基本群]]"`；若名称或公式包含会使 YAML 无法解析的字符，也应加引号。TeX 建议使用单引号，如 `'[[基本群|$\pi_1$]]'`。提示调用参数仍遵循普通 YAML，百科链接需加引号。

## 术语翻译

在百科正文任意位置使用 `terms` 数据块，声明一项或多项术语的译名。构建时按声明顺序汇总所有数据块，统一显示在全部学科导航下方、分类与最后修改时间之前；没有导航时也显示在正文末尾。每个术语是一段普通文字，标题与各语言译名接在同一行，窄屏自然换行。不同语言之间用圆点分隔，同一语言的多个译名用顿号分隔：

````markdown
```terms
群:
  en: group
  ja: 群<ぐん>
  fr: groupe :m
  de: Gruppe :f
位相空间:
  en: topological space
  ja: 位<い>相<そう>空<くう>間<かん>
```
````

语言使用代码，如 `en`、`ja`、`fr`、`de`、`ru`，显示时自动使用中文语言名称。保留字段 `lang` 不是译名，而是标注术语本身的语言，例如人名原文 `米田 信夫:` 下写 `lang: ja`。人物条目（属于“人物”分类及其子分类）的这一块标题显示为“译名”，其他条目为“术语翻译”。普通译名直接写字符串。末尾的空格加 `:m` 表示阳性，`:f` 阴性，`:n` 中性，`:mf` 通性，`:pl` 复数；不必声明名词词性。含冒号等 YAML 特殊字符时应给整个字符串加引号。

日语的 `字<假名>` 只给紧邻的一个 Unicode 字符注音，如 `群<ぐん>`、`位<い>相<そう>`。词组必须显式写成 `[词组]<假名>`，如 `'[位相]<いそう>'`；方括号只界定注音范围，不显示在页面上。`位相<いそう>` 仅给“相”注音；整体注音使用方括号写法。未标注的汉字、假名、标点和空格原样保留，如 `埋<う>め込<こ>み` 只标注“埋”和“込”，`位相空<くう>間` 只标注“空”。输出 HTML ruby，不支持 ruby 的阅读器通过括号回退显示读音。以方括号开头的 YAML 字符串需加引号。

简写与字段格式可混用。字段格式不解析简写，适用于复杂数据或需要保留字面文字的情况：

```yaml
群:
  fr: {text: groupe, gender: m}
位相:
  ja:
    text: 位相
    reading: [い, そう]
嵌入:
  ja:
    text: 埋め込み
    reading: [う, null, こ, null]
位相空间:
  ja:
    text: 位相空間
    ruby:
      - {text: 位相, reading: いそう}
      - {text: 空, reading: くう}
      - {text: 間, reading: かん}
```

`reading` 为列表时与 `text` 的 Unicode 字符逐字对应，无需注音的字符填 `null`；为字符串时给整个词注音。`ruby` 是可选的分段列表，分段合并后必须与 `text` 完全一致。`reading` 与 `ruby` 不能同时填写，二者只用于日语。可选 `note` 添加附注。同一语言有多个译名时用列表，如 `en: [first term, second term]`，也可以混合字符串与字段对象。

术语、译名、假名和附注按普通文字输出，不展开 Markdown、HTML 或百科链接，但与正文一样做排版替换（公式除外，日语译名除外）：直引号按上下文成为弯引号，撇号写作 `'` 即可（`Hilbert's basis theorem` 显示为 Hilbert’s basis theorem，`théorème d'Euler` 显示为 théorème d’Euler），`--` 显示为 `–`，`...` 显示为 `…`；术语和译名中的行内公式（如 `$\infty$-范畴:`、`en: $\infty$-category`）照常渲染。带注音的日语译名中，公式写在注音之外，如 `$L^p$ 空<くう>間<かん>`；公式内的 `[`、`<` 不按注音写法解析，注音的基字或 `[词组]` 不能含公式。含 `$` 的术语名作为 YAML 键时可以不加引号。`terms` 位于百科正文层级，不放在定理/证明环境、列表或引用块中。普通代码围栏中的示例保持原样。重复键、未知字段、空译名、无效性别或注音不对应会报出源文件与行号。`termTranslations` 元数据保留给生成流程，不手工填写。数学家传记的统一译名记录尚未实现。

## 正文内的人名标注

首次出现时在姓名之后写 `<person … />` 标签，后文可直接写姓名：

```markdown
这一结果由中文姓名 <person original="原文姓名" lang="ru" translit="拉丁转写" ipa="/…/" years="1900--1980" /> 证明。
```

上面使用占位文字演示格式。标签只输出姓名之后的注释，姓名本身照常书写（可以加粗）；`original`、`lang`、`translit`、`ipa`、`years` 都可省略，但至少要有 `original`、`translit`、`ipa`、`years` 之一。`lang` 标记原文姓名的语言。`years` 按行内 Markdown 渲染（`--` 成为短横线）。IPA 保留作者填写的 `/…/` 或 `[…]` 分隔符；`years` 是生卒年等简短文字。输出“中文姓名（俄语 原文姓名，拉丁转写 *拉丁转写*，IPA /…/，1900–1980）”，省略未填写的部分；最前面的语言名称取自 `lang`（名称表在 `data/language_names.yaml`，与术语翻译一致），“俄语”“拉丁转写”“IPA”等标注文字字号较小，转写用斜体。姓名与标签之间的空格由排版去掉。日语原名可用与术语翻译相同的注音写法，如 `original="[米田]<よねだ> [信夫]<のぶお>"`、`original="米<よね>田<だ>"`，显示为 ruby。字段按普通文字输出，不展开 Markdown、公式或百科链接。参数都写成 `名称="值"`，未知字段或缺少姓名会报错。

`npm run serve` 启动时运行 prebuild，再启动 Hugo 预览服务器。保存、添加、删除或重命名 `content/` 内的文章、附件和组件定义，或修改 `data/categories.yaml`，都会自动重新预处理并触发 Hugo 刷新。连续保存会合并处理，转换过程中的新改动会排队；预处理失败时保留上次成功的内容，修正后保存即可重试。模板和样式仍由 Hugo 自行监听。按 Ctrl+C 同时停止监听与 Hugo。

Hugo 参数可以透传，例如 `npm run serve -- --port 1414 --buildDrafts`。预处理先在临时目录完成转换，再同步变化的文件到 `.build/content/`。未变化的文件保持原样；附件变化时还会刷新所属页面包的首页，使 Hugo 重新读取资源。

`npm test` 验证分类、链接、公式、节与定理编号、首节前整数编号、星号环境与节标题、字面星号转义、有序列表编号及重排、统一引用、作者简写与加粗范围、自定义文献 label、五类文献、多块消歧、目录和嵌套引用、保护区域、错误定位、滚动偏移和 Hugo 最终输出。直接运行 Hugo 不会重新预处理源文章；开发预览使用 `npm run serve`。

本文介绍定义、定理等环境与证明的写法。

## 定理环境

定义、定理等内容写在以 `:::` 开头和结尾的环境中：

```markdown
::: theorem [万有系数定理] {@thm:uct}
设 $X$ 是拓扑空间，$A$ 是 Abel 群，则...
:::
```

第一行依次写定理类型、定理标题、引用标签，这些必须在同一行里。
标题和标签都可以省略：

```markdown
::: definition
定义的正文。
:::

::: lemma {@lem:key}
引理的正文。
:::

::: remark [关于系数]
注的正文。
:::
```

定理环境的正文**不要缩进**。在 Markdown 中，缩进的内容会变成代码块。

可用的定理类型如下：

| 类型 | 显示 |
| --- | --- |
| `definition` | 定义 |
| `theorem` | 定理 |
| `proposition` | 命题 |
| `lemma` | 引理 |
| `corollary` | 推论 |
| `conjecture` | 猜想 |
| `example` | 例 |
| `exercise` | 习题 |
| `remark` | 注 |
| `notation` | 记号 |
| `convention` | 约定，见下文 |

### 不编号的环境

类型后加 `*`，环境不编号，也不占用编号：

```markdown
::: theorem* [存在性]
定理的正文。
:::
```

### 自定义名称的环境

上表之外的名称（如讲义中的“条件”“元定理”“应用”）写在类型后的圆括号中，
代替“定义”“定理”等名称显示；编号和框的颜色仍按类型，引用时显示“条件 2.3”：

```markdown
::: definition (条件) [同分布] {@cond:same}
正文。
:::
```

名称是普通文字，不能含公式或括号。加 `*` 则不编号，如 `::: remark* (异议)`。

只出现一次、不需要编号的段落，可以在定理类型前加 `-`，只显示方括号中的标题，
不显示“注”“定理”等名称，也不编号；定理类型只影响框的颜色：

```markdown
::: -remark [回忆]
正文。
:::
```

## 证明

证明写在 `proof` 环境中，放在定理之后：

```markdown
::: theorem [基本性质] {@thm:basic}
定理的正文。
:::

::: proof
证明的正文。
:::
```

证明可以有标题，标题代替“证明”二字显示：

```markdown
::: proof [@thm:basic 的证明]
...
:::
```

## 约定

`convention` 环境用于说明全文采用的约定，不编号：

```markdown
::: convention
在本文中，环都指交换环。
:::
```

我们不推荐使用这一环境。
我们推荐在正文中使用完整术语，并在使用术语、记号时阐明其含义，而不是在文章开头做冗长的解释。
